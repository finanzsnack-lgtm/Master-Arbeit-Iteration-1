# Doku — Entwicklungsstationen des Reisebot-Prototyps

Dieser Ordner zeigt, **wie sich das Programm über die Zeit verändert hat**: von der ersten
regelbasierten Version bis zum aktuellen Stand. Er ist als Grundlage für die Masterarbeit gedacht
(Design Science Research nach Peffers et al. 2007 verlangt explizit, den Entwicklungsprozess und
die Begründung einzelner Design-Entscheidungen nachvollziehbar darzustellen) — hier soll sichtbar
werden, was probiert, was verworfen und was wie angepasst wurde, nicht nur der Endzustand.

## Warum dieser Ordner existiert (statt nur `ENTSCHEIDUNGSLOG.md`)

[`../ENTSCHEIDUNGSLOG.md`](../ENTSCHEIDUNGSLOG.md) ist die **vollständige, chronologische**
Was/Warum-Quelle — jede nicht-triviale Design-Entscheidung landet dort laufend, in der Reihenfolge,
in der sie getroffen wurde. Dieser Ordner ordnet dieselben Informationen zusätzlich **nach
Entwicklungsstationen** (jede Station = ein eigener Unterordner), damit man einzelne Abschnitte des
Programms gezielt aufschlagen kann, ohne das gesamte Log zu lesen — und damit dort, wo der
tatsächliche Code einer Station noch vorliegt, ein **echtes Duplikat** dieses Codes danebenliegt
(Unterordner `code_stand/`), statt nur einer Beschreibung.

## Wichtige Einschränkung: kein Git in diesem Projekt

Das Projekt hat **kein Versionskontrollsystem** (bewusste Entscheidung, siehe Rückfrage vom
12.08.2026 — Alternative wäre `git init` gewesen, aber Nutzerentscheidung: nur Ordner-Duplikate).
Das bedeutet:

- Der exakte Code **früherer** Stationen ist, wo er seither überschrieben oder gelöscht wurde,
  **nicht mehr rekonstruierbar**. Für Station 1 (regelbasierte Dialogsteuerung, gelöscht in
  Stage 2) gibt es deshalb NUR eine Textbeschreibung, keinen Code-Duplikat — bewusste
  Nutzerentscheidung, um in der Arbeit nichts als "Original" auszugeben, was in Wahrheit aus dem
  Gedächtnis rekonstruiert wäre.
- **Ab jetzt** gilt die Konvention: **bevor** eine nicht-triviale Architektur-/Infrastruktur-
  Änderung umgesetzt wird, werden die betroffenen Dateien zuerst 1:1 in einen neuen
  `doku/NN_stageX_.../code_stand/`-Unterordner kopiert (echtes Duplikat, keine Rekonstruktion) —
  danach erst wird der eigentliche Code geändert. So bleibt "so sah's vorher aus" exakt erhalten,
  auch ohne Git.
